# Support

Use the repository's issue templates for reproducible bugs and focused feature requests.

Before opening an issue:

1. run the zero-LLM checks from [CONTRIBUTING.md](CONTRIBUTING.md);
2. confirm the problem still occurs on the current `main` branch or latest release;
3. remove secrets, private repository content, customer data, and sensitive prompts from logs or screenshots;
4. include the PingPong version or commit SHA and relevant Codex / Claude Code / Python versions.

For installation or critic-path problems, include whether `doctor.ps1` passed and whether `$pingpong self-test` was run.

For security-sensitive reports, follow [SECURITY.md](SECURITY.md) instead of posting exploitable details publicly.
